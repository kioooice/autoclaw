# 第八章：安全与用户认证

## 一句话总结
代码写得再好，密钥一泄露全白搭。安全从第一行代码开始就要考虑。

---

## 小明的教训

把 `.env` 文件推到了 GitHub → 10 分钟内 OpenAI API Key 被盗用 → $127 账单

**关键点：**
- 互联网上有爬虫 24 小时扫描 GitHub，找密钥
- 从密钥出现到被盗用，平均只要 **5 分钟**
- 删掉文件没用——Git 历史记录还在

---

## 密钥管理

| 规则 | 说明 |
|------|------|
| 密钥永远不进代码 | 存在 `.env` 文件里 |
| `.env` 必须进 `.gitignore` | 防止推到 GitHub |
| 云端单独配置 | 部署平台的环境变量页面粘贴进去 |
| 泄露了立刻重置 | 不要抱侥幸心理 |

**Server vs Client 变量：**
- `DATABASE_URL` → 只在服务器用（绝不能暴露给浏览器）
- `NEXT_PUBLIC_XXX` → 浏览器能拿到（只放不敏感的配置）

## 认证方式

### Session vs Token

| 方式 | 原理 | 适合场景 |
|------|------|---------|
| Session | 服务器存登录状态，给浏览器一个"门票"（Cookie） | 传统 Web 应用 |
| Token (JWT) | 服务器发一个"身份证"，每次请求带上 | API / 移动端 |

### 登录方式

| 方式 | 说明 |
|------|------|
| 邮箱+密码 | 最基础，注意密码要哈希存储 |
| OAuth（第三方登录） | "用 GitHub/Google 登录"，不用自己管密码 |
| Passkeys（无密码） | 指纹/面容识别，最安全但普及度还不够 |

**推荐：Better Auth** — 成熟的认证库，别自己写认证逻辑（容易出安全漏洞）

---

## 路由保护

### Middleware：门卫
用户访问任何页面前，先检查登录状态。没登录 → 跳转到登录页。

### CORS：谁能调我的 API
限制只有你的前端域名能调用 API，防止别人拿走你的接口乱用。

### 权限控制
- **页面级**：没登录看不到管理后台
- **接口级**：普通用户不能调管理员接口
- **数据级**：用户只能看自己的订单（RLS）

---

## 常见安全威胁

| 威胁 | 是什么 | ORM 已防？ |
|------|--------|-----------|
| SQL 注入 | 在输入框里塞恶意 SQL | ✅ ORM 自动参数化 |
| XSS | 在页面里注入恶意脚本 | 框架基本防护，但仍要警惕 |
| CSRF | 伪装你的身份发请求 | SameSite Cookie 防护 |
| 密钥泄露 | 密码/API Key 暴露 | 靠你自己管好 `.env` |

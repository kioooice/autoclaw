# 6.2 数据库基础概念

## 一句话总结
把数据库想象成**超级 Excel**，搞懂表、行、列、主键、外键、三种关系就够了。

---

## 核心概念速查

| Excel 概念 | 数据库概念 | 说明 |
|-----------|-----------|------|
| 一个 Sheet | **表 (Table)** | 一类数据一张表 |
| 一行数据 | **行 (Row)** | 一条具体记录 |
| 表头 | **列 (Column)** | 数据的属性 |
| 身份证号 | **主键 (Primary Key)** | 每行唯一标识 |
| 索引线索 | **外键 (Foreign Key)** | 把两个表连起来 |

---

## 主键：每行的身份证
- ✅ 唯一、不能为空、不可变
- **最佳实践：** 用无业务含义的自增 ID，不用手机号当主键

---

## 外键：表与表之间的线索
**好处：**
1. 保证数据一致性（不能给不存在的用户创建订单）
2. 建立关联（从订单追溯到用户）
3. 级联操作（删用户时自动处理订单）

**⚠️ 必须手动加索引！** PostgreSQL 不会自动给外键建索引。

---

## 三种关系

### 1️⃣ 一对多（最常见）
一个用户 → 多个订单
**实现：** 在"多"的那张表加外键列

### 2️⃣ 多对多（需要中间表）
一个订单 → 多道菜，一道菜 → 多个订单
**实现：** 加中间表，拆成两个一对多

### 3️⃣ 一对一（拆分大表用）
用户基本信息 ↔ 用户详细资料
**实现：** 外键列加 UNIQUE 约束

---

## 约束：数据库的"安检门"
- PRIMARY KEY → 身份证号（唯一标识）
- FOREIGN KEY → 引用必须存在
- NOT NULL → 不允许为空（表单必填项）
- UNIQUE → 不允许重复（手机号不能重复注册）
- CHECK → 自定义条件（年龄必须 > 0）
- DEFAULT → 默认值（订单状态默认"待支付"）

**为什么数据库层面还要约束？**
1. 代码可能有 bug，数据库约束是最后防线
2. 数据入口不止一个，数据库约束定义一次全部受保护
3. 脏数据清理成本极高，预防比治疗便宜

---

## 数据类型速查
- serial → 自增主键
- text → 文本（**永远用 text，别用 varchar**）
- integer → 整数
- boolean → true/false
- timestamptz → 带时区时间（**别用 timestamp**）
- jsonb → JSON 数据
- numeric(10,2) → 精确小数（**钱必须用这个**）

**常见坑：** 金额用 float → 精度问题；时间用 timestamp → 不带时区

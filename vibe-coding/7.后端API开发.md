# 第七章：后端 API 开发

## 一句话总结
前端和数据库之间需要一座桥——API。前端发请求，后端处理数据，数据库存储。

---

## 为什么需要后端？

**前端不能直接连数据库！** 原因：
- 用户打开 F12 就能看到数据库密码
- 能随意删除别人的数据
- 无法做权限控制

**三层架构：**

| 层 | 职责 |
|---|------|
| 前端 | 展示界面、收集输入、发 HTTP 请求 |
| API（后端） | 接收请求、验证参数、操作数据库、返回响应 |
| 数据库 | 存储和检索数据 |

**API 是数据库的守门员，所有数据操作必须通过它。**

---

## 路由：URL 决定你看到什么

每天都在用路由，只是没意识到：
- `douban.com/` → 首页
- `douban.com/subject/37311135` → 某电影详情
- `douban.com/chart` → 排行榜

**Next.js 的文件系统路由：** 文件夹结构就是 URL 结构
```
app/
├── page.tsx           → yourdomain.com/
├── subject/[id]/
│   └── page.tsx       → yourdomain.com/subject/123
└── api/movies/
    └── route.ts       → yourdomain.com/api/movies（返回数据）
```

- `page.tsx` → 返回用户看到的**页面**
- `route.ts` → 返回程序用的**数据**（JSON）

---

## HTTP 方法：GET / POST / PATCH / DELETE

| 方法 | 含义 | 例子 |
|------|------|------|
| GET | 读取 | 获取电影列表 |
| POST | 创建 | 创建新电影 |
| PATCH | 更新 | 修改电影信息 |
| DELETE | 删除 | 删除电影 |

---

## 参数的三种来源

| 类型 | 位置 | 例子 |
|------|------|------|
| 路径参数 | URL 路径里 | `/movies/37311135` → 37311135 |
| 查询参数 | URL `?` 后面 | `/comments?status=P` → 只看看过的评论 |
| 请求 Body | 看不到（在请求体里） | 表单数据打包成 JSON 发给后端 |

---

## RESTful 风格

**核心思想：** 用 URL 表示资源，用 HTTP 方法表示操作
- `GET /api/movies` → 获取电影列表
- `POST /api/movies` → 创建新电影
- `DELETE /api/movies/123` → 删除 id=123 的电影

**跟 AI 说"用 RESTful 风格"，它就懂了。**

---

## 统一响应格式

约定好格式，前端处理一致：
```json
// 成功
{ "success": true, "data": { ... } }

// 失败
{ "success": false, "error": { "message": "..." } }
```

---

## 你的工作流

不需要手写每个接口，告诉 AI 需求就行。你的工作是验证：

1. **跑起来了吗？** → `pnpm dev` 启动，页面能正常操作
2. **数据库对吗？** → 打开 Drizzle Studio，看数据是否正确写入
3. **报错了吗？** → 把终端报错整段复制给 AI，让它修

**知道每个文件的职责，出问题时能告诉 AI "改哪个文件"就够了。**

## 关键词速查

| 词 | 什么意思 |
|----|---------|
| RESTful | API 命名规范 |
| GET/POST/PATCH/DELETE | HTTP 方法 |
| 路径参数/查询参数/Body | 参数三种来源 |
| route.ts | Next.js 的 API 接口文件 |
| 统一响应格式 | success + data/error |
| tRPC | 另一种 API 风格（像调本地函数），见到不用慌 |

# 第十四章：云服务器运维与项目部署

## 一句话总结
想要完全控制权？买台 VPS，SSH 连上去，用 Docker 装应用，自己掌控一切。

---

## 什么时候需要自己的服务器？

- Serverless 平台限制太多
- 想装平台不支持的东西（数据库、监控、自动化工具）
- 想完全掌控运行环境

---

## SSH：远程连接服务器

```bash
ssh root@你的服务器IP
```

第一次连接会问你确认指纹 → 输入 `yes` → 输入密码 → 进来了！

**连接上的是一个没有桌面的 Linux 命令行。**

---

## 安全第一：锁好门窗

裸奔的服务器上线几分钟就会被扫描到。

**必做安全措施：**
- ✅ 更新系统
- ✅ 配置安全组（云厂商的防火墙）
- ✅ 改 SSH 端口（不用默认 22）
- ✅ 装 Fail2Ban（自动封禁暴力破解的 IP）
- ✅ 禁用 root 密码登录（用 SSH 密钥）

---

## 1Panel：服务器管理面板

命令行不友好？装 1Panel → 浏览器里管理服务器

**核心是 Docker**，一键安装应用。

---

## Docker：集装箱比喻

每个应用被打包在独立的"集装箱"里运行：
- 互不干扰
- 不会弄脏服务器系统
- 装错了？删掉重来

**铁律：永远不要直接在服务器上写代码！**
本地开发 → Git 推上去 → 服务器跑代码

---

## 安全组：云厂商的门禁

默认只放行 SSH（22 端口），其他端口全锁着。

装了新应用要用新端口 → 去云厂商控制台开放对应端口

**访问不了面板？** 大概率是安全组没开端口。

---

## 自建数据库

1Panel 应用商店一键安装 PostgreSQL。

**DBMS vs Database：**
- PostgreSQL（DBMS）= Excel 软件本身
- Database = Excel 里打开的一个 .xlsx 文件
装一次 PostgreSQL，可以创建无数个数据库。

---

## 容器网络

**关键概念：** 每个容器的 `localhost` 是它自己，不是服务器。

| 场景 | 用什么 |
|------|--------|
| 容器找邻居 | 容器名（如 `postgresql`） |
| 主机找容器 | `localhost` 或 `127.0.0.1` |
| 外部访问 | 公网 IP + 映射端口 |

**DATABASE_URL 填错了？** → 检查主机名该用容器名还是 localhost

---

## 端口映射

服务器一个 IP，多个应用怎么跑？
```
服务器 IP:3001 → 容器 A（监听 3000）
服务器 IP:3002 → 容器 B（监听 3000）
```

**一栋楼一个地址，端口号就是房间号。**

## 日志：出了问题怎么看

不要猜，看日志！1Panel 点容器的"日志"按钮。

**新手关注三个关键词：**
- `Error` → 错误，看具体信息
- `Warning` → 值得检查
- 你自己写的日志 → 帮你定位执行到哪

**常见模式：**
- "找不到模块" → 依赖没装好
- "连接被拒绝" → 数据库地址错了或没启动
- "超时" → 网络问题或代码逻辑问题

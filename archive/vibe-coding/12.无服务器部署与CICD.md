# 第十二章：无服务器部署与 CI/CD

## 一句话总结
`git push` → 自动构建 → 自动上线。部署变成了"保存即发布"。

---

## 为什么需要部署？

内网穿透关了就失效。需要一个**永久在线**的地址。

---

## Serverless（无服务器）是什么？

不是真的没有服务器，而是**你不需要管理服务器**。平台帮你处理扩容、维护。

---

## 部署平台选择

| 平台 | 国内速度 | 成本 | 适合 |
|------|---------|------|------|
| **腾讯云 EdgeOne Pages** | 🚀 快 | 免费额度慷慨 | 国内用户为主 |
| **阿里云 ESA** | 🚀 快 | 免费额度充足 | 国内项目 |
| **Vercel** | 🐢 国内慢 | 免费版有限制 | 海外用户 |
| **Cloudflare Pages** | 🌍 均衡 | 免费额度大 | 全球用户 |
| **GitHub Pages** | 🐢 国内慢 | 完全免费 | 纯静态网站 |

**国内项目推荐：EdgeOne 或 ESA**

---

## CI/CD 是什么？

**CI = 持续集成**（代码合并后自动测试）
**CD = 持续部署**（测试通过后自动部署）

**实际流程：**
```
你 git push
  → GitHub 通知部署平台
  → 平台自动拉代码、安装依赖、构建
  → 构建成功 → 自动上线
```

**你不需要手动操作！**

---

## 部署配置要点

| 配置 | 说明 |
|------|------|
| 框架预设 | 选 Next.js，平台自动填充推荐配置 |
| 构建命令 | 默认 `pnpm build` |
| 输出目录 | Next.js 通常是 `.next` 或 `out` |
| Node 版本 | 调整为和本地一致（本教程用 24） |
| 环境变量 | **单独配置**（.env 不在 Git 里） |

---

## 常见踩坑

| 问题 | 原因 | 解决 |
|------|------|------|
| 构建失败 `Failed` | Node 版本太旧 | 平台设置里改 Node 版本 |
| 网页全是报错 | 环境变量没配 | 在平台"环境变量"页面粘贴 .env 内容 |
| 页面 404 | 路由配置不对 | 检查输出目录设置 |

**国内平台通常支持批量导入环境变量** — 直接粘贴整个 .env 文件内容。

---

## 预览部署

每次 push 会生成一个**预览链接**（非主分支），方便测试后再合并上线。

---

## 灰度发布

先给 10% 用户推送新版本 → 观察没问题 → 扩大到 50% → 全量

**个人项目不需要，但理解这个概念有用。**

---

## CDN（内容分发网络）

全球部署缓存服务器，用户从最近的节点获取内容 → 全球都快

**现代部署平台都内置 CDN，不需要额外配置。**

---

## 缓存的三层

| 层 | 在哪 | 说明 |
|---|------|------|
| 浏览器缓存 | 用户电脑 | 访问过的资源存本地 |
| CDN 缓存 | 全球节点 | 离用户最近的服务器返回内容 |
| 服务端缓存 | 服务器内存 | 缓存计算结果，避免重复计算 |

**页面更新了用户看不到？** → 可能是缓存，`Ctrl+Shift+R` 强制刷新

---

## 成本优化

| 阶段 | 用户量 | 策略 |
|------|--------|------|
| MVP | < 1000 | Serverless 零成本起步 |
| 增长 | 1000-10000 | 评估是否需要混合架构 |
| 企业 | > 10000 | 考虑自建或优化 |

**过早优化是万恶之源！**
